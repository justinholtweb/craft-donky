Numbering

Numbers that
hold up

One place hands out a number, under a mutex, with a unique index behind it.

  • Reset yearly, monthly or daily — a real counter per period
  • Voiding keeps the number; deleting keeps it spent
  • Or borrow order.reference, and the invoice number is the order number
INV-{yyyy}-{number}→INV-2026-0142
PS-{number}→PS-000317
CN-{yy}{mm}-{number}→CN-2601-0044
{storeHandle}-{yyyy}-{number}→US-2026-0091

Templates

No layout
builder

Every document is a Twig template. Copy the bundled folder, point the type at your copy, own it outright.

  • The Designer still feeds it your logo, colours and issuer block
  • The design produces the stylesheet, so your own markup gets them free
{# templates/donky/_render/invoice.twig #} <table class="lines"> {% for line in snapshot.lines ?? [] %} <tr> <td>{{ line.description }}</td> <td>{{ document.money(line.total) }}</td> </tr> {% endfor %} </table> {# Guard every snapshot read — devMode sets strict_variables #}

Console

Rehearses
before it writes

Backfill a year of orders with a dry run first, oldest order first, each document dated when the order happened.

  • Otherwise a yearly sequence files last year's invoices under this year's numbers
  • Issue, re-render and list from the command line too
$ php craft donky/documents/backfill --type=invoice --dryRun Scanning completed orders with no invoice … ORD-0881 2025-01-14 → INV-2025-0001 ORD-0882 2025-01-14 → INV-2025-0002 ORD-0883 2025-01-16 → INV-2025-0003 … 1,204 more Dry run — nothing was issued, no number was spent. $ php craft donky/documents/backfill --type=invoice --limit=500 ✓ 500 invoices issued, INV-2025-0001 … INV-2025-0500
